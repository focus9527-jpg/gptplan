Microduck 个人样机复刻方案

从双舵机台架开始，逐步完成双足骨架、运动闭环与鸭形外壳。

总预算 ≤ ¥500015个执行器借用3D打印机预计12–16周

01 · 项目定义

制造一台可拆装维护的 Microduck 风格双足样机，复用官方运动软件与训练框架，自行完成骨架、供电和驱动适配。已有电脑、借用朋友的打印机；总现金支出不超过 5000 元，不含人工和已有设备。

本文件是完整实施规划，不是经过实机验证的制造图纸。国内采购报价、具体主控和IMU型号、供电额定值、打印装配件仍需通过下述审查和台架测试确定。
指标首版目标
尺寸与质量高度约25 cm；质量以约800 g为目标，超重时重新验证力矩与模型
关节两腿各5轴、颈头部4轴、独立喙部1轴
必做功能站立、低速行走、转向、坐下、头部动作、喙部开合
遥控电脑经Wi-Fi发送指令；台架可使用有线连接
第二阶段跌倒起身、轻物抓取、摄像头；按余额逐项增加
延期功能ToF、NFC、语音、轮滑

02 · 已知资料与边界

官方产品为15电机双足机器人，约25 cm、780–800 g，采用RK3566、摄像头、8×8 ToF、身体与头部IMU、NP-F550电池。产品参数不等于本样机的验收承诺。官方明确开源范围为软件，机械和电子设计文件没有完整开源。

训练项目公开MuJoCo模型、执行器建模、PPO训练与ONNX导出。模型中的14个策略控制关节为两腿10轴及颈头4轴；喙部驱动的接线和软件映射须进一步核查。软件复用与实物可打印性分别审查。

运行与训练软件采用Apache-2.0；训练仓库注明3D模型采用CC BY-SA-NC。记录模型来源、许可和修改信息；面向商业用途时另行核查适用范围。

事实依据见文末官方来源。预算、工期、重量分配和验收次数均为本方案的工程目标。

04 · 系统架构与选型原则

电脑遥控 → Linux主控 → 半双工TTL接口 → 15个舵机
身体/头部IMU → 姿态与关节观测 → ONNX策略 → 关节命令
电池 → 保护与总开关 → 舵机稳压支路 / 主控稳压支路

优先复用官方运行栈。审查目标CPU架构、系统库、GPIO/I²C/UART及硬件依赖，随后选定主控。ARM板并不自动兼容官方整机服务；必要时适配硬件层，保留观测、动作与策略接口。

选择XL330是为了降低执行器模型差异。厂商页面列出单个18 g、标称5 V、位置/速度/电流等反馈；15个共约270 g。最终控制模式和增益应与所用官方版本核对，不凭型号直接套用。

IMU采购要求：有可靠Linux驱动或明确可实现的接口、采样时间戳、坐标系说明和稳定校准方式。首版用身体IMU完成姿态闭环；头部IMU在策略和服务依赖审查后接入。

05 · 机械设计与打印

先设计承力骨架，再做鸭形外壳。保留官方模型的关节轴线、连杆长度和活动范围作为起点；修改后同步更新仿真。仿真网格可能只用于显示或碰撞，不能直接视为带孔位、轴承座和装配公差的打印图纸。

部位设计要求
双腿髋偏航、髋侧摆、髋俯仰、膝、踝；关节方向逐轴核对
承力关节舵盘与对侧支撑共同承载；校核支撑轴、孔位和线束干涉
躯干电池接近躯干中心；主控轻量、散热通畅、可独立拆卸
头部与喙控制头部质量；喙设置限位并避免夹线，首版验证开合
脚底可换防滑垫；先参考官方几何，测试后调整
外壳薄壁、可拆、避开关节与散热；不承担首轮步态试验载荷

打印顺序：安装与孔位试块 → 单关节 → 一条腿 → 全身骨架 → 最终外壳。先用PLA验证装配；承力件材料和打印方向通过负载试验决定。不要未经试块验证就打印整套结构。

CAD交付：参数化源文件、STEP、打印STL/3MF、零件编号、材料与方向、数量、装配图。记录实际重量；软件中使用测量值。

06 · 供电与保护

台架用可限流电源；若没有可借设备，购买费用需从预算内调整。电池方案在实际电流测量后确定，不提前锁定容量和稳压电流。

XL330厂商页面列出5 V标称电压及1.47 A堵转电流。15个同时堵转的算术值为22.05 A，这不是正常工作电流，但说明必须评估峰值和故障负载。不得将两串锂电池直接连接到5 V舵机。

  1. 按单关节、单腿、整机三个阶段记录电流、供电电压和温升。
  2. 根据实际峰值、持续负载和允许电压范围选择稳压、连接器及线径。
  3. 主控与舵机使用分开的稳压支路，合理共地并检查压降。
  4. 设置总开关及可立即断开舵机支路的开关。
  5. 加入通信超时、命令限位、温度及欠压处理。

通信丢失的正常停止流程：先清零移动指令，在姿态有效且机器人稳定时进入站立/坐姿；观测异常或危险故障按预定策略处理。直接断舵机电源会失去支撑，调试时使用吊绳和软垫。

07 · 软件、标定与策略

分别固定microduck运行栈与microduck_rl训练栈的提交SHA，记录依赖、模型和策略来源。首轮仅实现基础运动闭环，其他服务按依赖逐项启用。

  1. 通信：发现舵机、逐个配置ID、读反馈、同步写入、记录超时与错误。
  2. 标定：确认机械中位、方向、软件限位及关节数组顺序，低速验证。
  3. 观测：校准IMU、核对坐标系与时间戳，按所用策略构造输入。
  4. 推理：使用官方导出路径生成ONNX；核对归一化、输入输出形状和关节顺序。
  5. 控制：验证50 Hz策略节拍下的读写与推理预算，记录延迟，不将50 Hz等同于舵机内环频率。
  6. 遥控：速度指令、模式切换、急停和状态显示；限制首轮速度。

当前训练仓库文档描述61维观测与14维策略输出，版本可能变化，实施时以固定提交为准。喙部独立控制与策略切换需要核对运行栈。

调试顺序：单舵机 → 单腿 → 全身悬空 → IMU方向 → 仿真推理 → 吊绳站立 → 低速行走 → 转向 → 坐下 → 起身。每层通过后进入下一层。

08 · 仿真到实机

现成策略只在仿真和保护条件下逐步验证，不能假设同型号舵机意味着直接可用。实际几何、质量、惯量、脚底摩擦、间隙、控制延迟和电压变化均影响步态。

参数测量或更新方法
几何与质量CAD与称重，记录每个连杆
重心与惯量CAD估算；整机支撑测试辅助校核
零位与活动范围装配标定与全行程干涉检查
延迟与响应命令/反馈日志和带载测试
间隙与摩擦方向反转测试和不同地面试验
供电变化带载电压与电流记录

故障排查顺序：接线与供电 → ID/方向/零位 → 观测与时序 → 参数与策略 → 重训。训练框架需要CUDA GPU；已有GPU则本地训练，否则借用或租用并限制支出。没有GPU也能先完成硬件和推理验证。

09 · 分批采购与进度

按每周10–15小时估算，计划12–16周；采购等待、经验差异和重训会改变工期。

阶段工作与采购进入下一阶段条件
第1–2周固定版本、审查资产、国内询价、完整BOM；不采购全套预算成立，模型与许可清楚
第3–4周第一批2个舵机、接口、身体IMU、供电；700–1000元内，从总预算扣除通信、反馈、带载与仿真推理通过
第5–7周设计单腿，验证打印；随后补齐其余13个舵机和骨架材料单腿装配无干涉，完整采购仍留余量
第8–9周全身装配、线束、IMU、零位和悬空测试轴映射正确，供电稳定
第10–13周保护下站立，低速步态，转向与坐下基础验收通过
第14–16周电池、外壳、耐久测试、文档；按余额增加功能最终验收与支出核对

10 · 验收与问题处理

测试通过标准
静止站立每次60秒，5次全部通过
前进平地3米，5次至少4次成功；记录地面、速度和电池状态
转向与停止左右转向并恢复稳定站立
基本动作坐下、头部动作、喙部开合可重复执行
续航20分钟规定动作循环，无主控重启与持续总线故障
失联与保护模拟遥控断开、异常观测；符合预定处理流程
维护可独立拆换舵机、电池、主控，标定可恢复
成本所有实际支出合计≤5000元

出现反复跌倒：先检查方向、零位、IMU与时序，再查脚底及重心。出现重启：检查稳压、线束压降与瞬态负载。出现发热：降低负载并检查机械卡滞与控制参数。出现总线丢包：检查供电、连接、ID、波特率及读取预算。任何结构或参数修改都记录对应测试结果。
